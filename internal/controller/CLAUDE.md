# internal/controller

> controller-runtime reconcilers for every operator CRD (27 controllers, one per Kind: cluster, standalone,
> database, sharded database, composite database, alias, replica database, replica promotion, backup,
> restore, user, role, rolebinding, authrule, plugin, plus the 12 `aura*_controller.go` for the Aura CRDs),
> plus the shared helpers (events, conditions, clusterRef resolution, env-var/owned-key merging,
> split-brain detection, topology scheduling, rolling upgrade) they lean on.

## Key files

| File | What it does |
|---|---|
| `neo4jenterprisecluster_controller.go` | HA cluster reconciler. Owns the `{cluster}-server` StatefulSet, `mergeEnvVars`/`envVarsEqual`, `CollectDiagnostics`, fleet-management plugin merge. |
| `neo4jenterprisestandalone_controller.go` | Single-node reconciler (shares helpers via `standaloneAsCluster` in `util.go`). |
| `neo4jbackup_controller.go` | Job-per-`Neo4jBackup`-CR reconciler (invariant 5 — no long-running backup pod). `neo4jbackup_sharded.go`, `neo4jbackup_log_parser.go` support it. A one-time backup's terminal phase is read through `APIReader` when the cached copy is not terminal, and a succeeded run waits for its artifact names at most `artifactCaptureGrace` (knowledge `backup-restore.md` Rules 113, 174); sharded names are lower-cased as `neo4j-admin` writes them (Rules 48, 53). |
| `neo4jrestore_controller.go` | Restore reconciler (heaviest user of `RetryOnConflict` status writes). An all-databases restore announces its start once and each failed database once (`markDatabaseResult`); its progress events go through `ProgressRecorder`, an event source of its own, so they never spend the budget its outcome needs (knowledge `operations.md` id 166). A restore Job carries its attempt (`neo4j.com/restore-attempt`), and an attempt never adopts another's Job (`clearEarlierRestoreJob`, `backup-restore.md` Rule 46); a Job restore has one `RestoreStarted`, with the offline reason in it (`restoreJobStartedMessage`, id 145). |
| `neo4jdatabase_controller.go` / `neo4jshardeddatabase_controller.go` | `Neo4jDatabase` / `Neo4jShardedDatabase` reconcilers. Like the composite, alias and replica reconcilers, a database `Ready` at its generation stays `Ready` while its target restarts or does not answer (`waitForHost` / `waitForCluster`, on `noteTargetWait` in `target_wait.go`), and its Ready event follows the write that enters `Ready` (knowledge `operations.md` id 183); a `Neo4jDatabase` writes only its documented phases, never `Unknown` (`databasePhaseFor`, id 190). |
| `neo4juser_controller.go` / `neo4jrole_controller.go` / `neo4jrolebinding_controller.go` / `neo4jauthrule_controller.go` | Auth-model reconcilers. `role_resolution.go`: CR-name resolution and `missingRoles` (a role in `SHOW ROLES` exists; knowledge `operations.md` id 17). `target_wait.go`: `recordTargetWait` — a dependent `Ready` at its generation stays `Ready` while its target is not, and its Ready event follows the write that enters `Ready` (id 158), and one with another outcome of its own at its generation (a failure, `UserNotFound`) keeps it, so the same failure is not announced again after a restart (`settledAtGeneration`, id 189); `targetUnreachable` — a target that reads `Ready` but refuses the connection is the same wait (reason `ClusterUnreachable`), logged at info and reported only after `targetUnreachableGrace` (id 172). Each has a client seam tests script (`newNeo4jClient` / `newDeletionClient`). |
| `neo4jcompositedatabase_controller.go` / `neo4jdatabasealias_controller.go` / `neo4jreplicadatabase_controller.go` / `neo4jreplicapromotion_controller.go` | Composite DB, alias and cross-cluster replication reconcilers. Each `Reconcile` has a client seam tests script (`newNeo4jClient`), and keeps a `Ready` (`Replicating`) object so through a target restart (`waitForTarget`, `unreachable`; knowledge `operations.md` id 183). |
| `aura*_controller.go`, `aura_fleet_provision.go` | Aura (cloud) reconcilers on the Aura REST API (`internal/aura/`); no Bolt. Refusals must not reach an `aura.IsTransient` branch unmarked, and a step that returns one error from several calls retries only what `retryableAuraCall` marked at the Aura call (knowledge `operations.md` id 88). A status is written only when it changes or its `lastSyncedTime` is due a refresh, a refusal already on status is not asked again, and `fail()` writes phase `Error` (id 156); a deletion resolves the credentials only to call Aura, and waits for them `finalizerDeletionGracePeriod` (id 157). A status message built from an Aura error goes through `aura.MessageWithoutRequestID`, so a failure that repeats is the same status, and the `AuraProviderConfig` revalidates every 10 minutes, wired with no `RequeueAfter` (id 184). Helpers in `aura_common.go`. |
| `plugin_controller.go` | `Neo4jPlugin` reconciler; home of `MergeNeo4jPluginList`. Watches target StatefulSets so a `Ready` plugin restores what something removed, and nothing else (knowledge `operations.md` id 135); a write to the servers waits until the target is `Ready` with every server available and has rolled out its latest spec, and the plugin is `Ready` only once its own roll is done (id 141); it is the only writer of a `VerifiedDownload` plugin's `plugin-ca` volume, which follows the target's `spec.trustedCASecrets` (id 147). `plugin_target_gate.go` holds that gate (`targetRolloutPending`, `rolloutPending`) and its one exception, the write that changes what every down server keeps failing in — the plugin's own init container (id 152) or its settings (id 155) (`selfRepair`, `replaceStuckPods`). `plugin_env_ownership.go`: each plugin records the env vars it sets under `neo4j.com/plugin-env-vars.<plugin>` and its `NEO4J_PLUGINS` names under `neo4j.com/plugin-entries.<plugin>` on the StatefulSet, removes the ones it no longer sets (`applyPlugin`), makes a cluster's shared procedure lists what the plugins ask for now (`setClusterPluginLists`), and its uninstall takes away everything it wrote in one write (`removePluginFromTarget`; id 155). Nothing is set at runtime (no `dbms.setConfigValue`; id 135). `plugin_disabled.go`: `spec.enabled: false` takes the plugin off its target with that same write and keeps the CR, phase `Disabled` (id 160). `plugin_allowlist.go`: a plugin whose procedures the target's effective allowlist hides carries the `ProceduresHidden` condition (id 161). `plugin_refused.go`: a Managed plugin whose entrypoint name the target's image does not list is `Failed` (`PluginUnknownToImage`) and taken off the target with that same write, never written to `NEO4J_PLUGINS` (id 170), and so is one whose JAR the image does not run (n10s from 5.26.22). `plugin_target_absent.go`: a target whose StatefulSet does not exist yet, or for the seconds a storage expansion takes to create it again, is waited for with no event and no ERROR, and a `Ready` plugin stays `Ready` (`awaitStatefulSet`, id 177); a deleted plugin's finalizer waits, at most five minutes, until the standalone pod that keeps failing on it is replaced (`uninstallWaitsForStuckPod`, id 155). |
| `events.go` | All `EventReason*` string constants — emit these, never raw strings. A state event is announced from the status write that records it; `event_memory.go` (`lastAnnounced`) remembers, per object, a Normal event no status write records, so it is emitted when what it reports changes (knowledge `operations.md` id 136). |
| `fleet_plugin.go` | `addFleetManagementPlugin`: merges `fleet-management` into a template's `NEO4J_PLUGINS` — every pass's fleet merge, and the write that creates the StatefulSet of a deployment whose spec enables Aura Fleet Management, outside the owned-env record (knowledge `operations.md` id 175). ## Key types & functions

- `ResolveClusterRef(ctx, c, ns, name) (ResolvedTarget, error)` — tries cluster first, then standalone (`cluster_resolver.go`). `ResolvedTarget` exposes `IsReady`, `NewClient`.
- `EnqueueDependentsForClusterChange(...)` — watch wiring so user/role/binding reconcilers re-run on cluster status flips (used in each `SetupWithManager`).
- `SetReadyCondition` / `SetNamedCondition` (`conditions.go`) — `SetNamedCondition` for `ServersHealthy`/`DatabasesHealthy` etc.; `SetReadyCondition` ONLY for the `Ready` type.
- `(r *Neo4jEnterpriseClusterReconciler) envVarsEqual(...)` + package-level `mergeEnvVars(...)` (`neo4jenterprisecluster_controller.go`).
- `MergeNeo4jPluginList(existing, newPlugin)` (`plugin_controller.go`) — live-patch `NEO4J_PLUGINS` without clobbering other controllers.
- Each reconciler's `Reconcile` + `SetupWithManager`.

## Conventions & gotchas

- **Validation is INLINE, never a webhook (invariant 1).** Reconcilers hold a `*validation.*Validator` (e.g. cluster controller's `Validator *validation.ClusterValidator`) and call it from `Reconcile` — there is no `_webhook.go`.
- **Status writes wrap `retry.RetryOnConflict(retry.DefaultRetry, ...)`** (or `DefaultBackoff`) — required for 2025.01.0 cluster formation. See `neo4jenterprisecluster_controller.go` (`grep -n RetryOnConflict`). Re-fetch the object inside the closure.
- **Never `Update` one of the operator's CRs; patch what you change** — a finalizer, an annotation, a spec field (`object_patch.go`: `patchObject`, `addFinalizer`, `removeFinalizer`; knowledge `operations.md` id 150). An Update sends the whole object as the Go types encode it: the cluster reconcile's copy carries `ApplyDefaults`' defaults, a `false` the CRD defaults to `true` is omitted and comes back `true` (a `Neo4jRole`'s `enforcePrivileges: false` turned into revoking), and a quantity is re-spelled. `TestReconcile_LeavesTheSpecAsApplied_APIServer` and `TestFinalizers_LeaveEveryKindsSpecAsApplied_APIServer` (envtest) pin the writers. Child objects (StatefulSets, Services, ConfigMaps) are the operator's own and are not covered.
- **Per-server clients use the cluster's admin Secret with its default** (`getClusterAdminSecretName`; `dialClusterPod`, `createPodSpecificNeo4jClient`; knowledge `operations.md` id 132): never refuse a cluster without `spec.auth.adminSecret`.
- **StatefulSet existence check is `sts.UID != ""`, NOT `ResourceVersion`** (ResourceVersion is set even on never-created objects). See `createOrUpdateResourceInternal` in `neo4jenterprisecluster_controller.go`.
- **Emit events via `EventReason*` constants from `events.go`** with `corev1.EventTypeNormal` / `corev1.EventTypeWarning` — never raw strings.
- **Env vars: subset-merge, never wholesale-replace.** `envVarsEqual` checks desired vars exist with the right value but tolerates foreign extras; `mergeEnvVars` merges and enforces removals via the owned-keys annotation (`owned_keys.go`). Each `Neo4jPlugin` keeps the same kind of record of the vars it sets (`neo4j.com/plugin-env-vars.<plugin>`) and removes only what it recorded, never a var the target's own record or another plugin claims (knowledge `operations.md` id 155). Do not bake `NEO4J_PLUGINS` into the static StatefulSet template; use `MergeNeo4jPluginList`. (CLAUDE.md "Key Implementation Patterns".) Init containers and volumes of the server pod template follow the same model by name (`mergeOwnedByName`, `readOwnedTemplateItems`; knowledge `operations.md` id 141) — a `VerifiedDownload` plugin's init container is not the cluster's.
- **`CollectDiagnostics` is non-fatal** — surface errors to `status.diagnostics.collectionError`, never `return err`.
- **Server-based naming only**: `{cluster}-server-0…N-1`; never `primary-*`/`secondary-*` (invariant 5). `splitbrain_detector.go` enumerates pods by this scheme.

## Tests

`*_test.go` here run under the envtest suite (`suite_test.go`, no real cluster). Run the whole package with `make test-unit`, or directly: `go test ./internal/controller/...`. The core/extended ginkgo label split lives in `test/integration/`, not in this package. A single integration spec: `make test-one TEST="name"`.
