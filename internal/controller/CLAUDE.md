# internal/controller

> controller-runtime reconcilers for every operator CRD (27 controllers, one per Kind: cluster, standalone,
> database, sharded database, composite database, alias, replica database, replica promotion, backup,
> restore, user, role, rolebinding, authrule, plugin, plus the 12 `aura*_controller.go` for the Aura CRDs),
> plus the shared helpers (events, conditions, clusterRef resolution, env-var/owned-key merging,
> split-brain detection, topology scheduling, rolling upgrade) they lean on.

A one-time backup's terminal phase is read through `APIReader` when the cached copy is not terminal, and a succeeded run waits for its artifact names at most `artifactCaptureGrace` (knowledge `backup-restore.md` Rules 113, 174); sharded names are lower-cased as `neo4j-admin` writes them (Rules 48, 53). A failed backup Job says why in `status.message`, the `BackupFailed` event and the run's `status.history[].error` (one-time and scheduled): its condition and the tail of its last failed pod's termination message (`jobFailureMessage` in `job_failure.go`, shared with the restore; knowledge `operations.md` id 215). |
| `neo4jrestore_controller.go` | Restore reconciler (heaviest user of `RetryOnConflict` status writes). A missing target is announced once with `ClusterNotFound`, and a restore that ended at its generation is decided before its target is looked up (id 198). A target that cannot serve the all-databases loop for a moment (`allDatabasesTargetAway`: unreachable, or a transient Neo4j error — recreating `neo4j` makes it unavailable) is waited out in place (`awaitAllDatabasesTarget`: `ClusterNotReady=True`, info log, one `ConnectionFailed` only past 5 minutes), and `RestoreStarted` is announced only while no database of the attempt has started (id 206). A restore Job carries its attempt (`neo4j.com/restore-attempt`), and an attempt never adopts another's Job (`clearEarlierRestoreJob`, `backup-restore.md` Rule 46); a Job restore has one `RestoreStarted`, with the offline reason in it (`restoreJobStartedMessage`, id 145), and an online one too, with any `stopCluster` notice in it (`onlineRestoreStartedMessage`). `restore_outcome.go`: a refused spec is `Failed` and logged once at info, never an ERROR or a returned error (`refuseRestore`, `restoreRefusal`); a failed Job says why — its condition and the tail of its last failed pod's termination message (`restoreJobFailure`); the Ready condition has a restore's reasons (`restoreReadyCondition`; id 215); a restore that ended at its generation (`restoreEndedAtGeneration`) returns at the guard with no requeue and no write, its line at V(1) — the dev cache resyncs every 30 seconds — and a missing `spec.instanceRef` is refused after that guard (id 215). `onlineClient` (`restore_target.go`) is the online path's client seam. |
| `neo4jdatabase_controller.go` / `neo4jshardeddatabase_controller.go` | `Neo4jDatabase` / `Neo4jShardedDatabase` reconcilers. Like the composite, alias and replica reconcilers, a database `Ready` at its generation stays `Ready` while its target restarts or does not answer (`waitForHost` / `waitForCluster`, on `noteTargetWait` in `target_wait.go`), and its Ready event follows the write that enters `Ready` (knowledge `operations.md` id 183). A `Neo4jDatabase` writes only its documented phases, never `Unknown` (`databasePhaseFor`, id 190). `duplicate_names.go`: of two database, sharded database, composite or alias CRs of one kind that give one name on one target, ignoring case (Neo4j lower-cases names), the older owns it and the other is `Failed` with one `DuplicateName` and sends nothing; a deletion leaves the name to a live CR that still gives it (`DuplicateNameKept`), and a watch on the kind wakes the others of a name (`othersOfTheName`; id 217). |
| `neo4juser_controller.go` / `neo4jrole_controller.go` / `neo4jrolebinding_controller.go` / `neo4jauthrule_controller.go` | Auth-model reconcilers. `role_resolution.go`: CR-name resolution and `missingRoles` (a role in `SHOW ROLES` exists; knowledge `operations.md` id 17). `target_wait.go`: `recordTargetWait` — a dependent `Ready` at its generation stays `Ready` while its target is not, and its Ready event follows the write that enters `Ready` (id 158), and one with another outcome of its own at its generation (a failure, `UserNotFound`) keeps it, so the same failure is not announced again after a restart (`settledAtGeneration`, id 189); `targetUnreachable` — a target that reads `Ready` but refuses the connection is the same wait (reason `ClusterUnreachable`), logged at info and reported only after `targetUnreachableGrace` (id 172). Each has a client seam tests script (`newNeo4jClient` / `newDeletionClient`). |
| `neo4jcompositedatabase_controller.go` / `neo4jdatabasealias_controller.go` / `neo4jreplicadatabase_controller.go` / `neo4jreplicapromotion_controller.go` | Composite DB, alias and cross-cluster replication reconcilers. Each `Reconcile` has a client seam tests script (`newNeo4jClient`), and keeps a `Ready` (`Replicating`) object so through a target restart (`waitForTarget`, `unreachable`; knowledge `operations.md` id 183). |
| `aura*_controller.go`, `aura_fleet_provision.go` | Aura (cloud) reconcilers on the Aura REST API (`internal/aura/`); no Bolt. Refusals must not reach an `aura.IsTransient` branch unmarked, and a step that returns one error from several calls retries only what `retryableAuraCall` marked at the Aura call (knowledge `operations.md` id 88). A status is written only when it changes or its `lastSyncedTime` is due a refresh, a refusal already on status is not asked again, and `fail()` writes phase `Error` (id 156); a deletion resolves the credentials only to call Aura, and waits for them `finalizerDeletionGracePeriod` (id 157); a DELETE Aura refuses (not a conflict, not transient, not "not found") waits the same time, then releases with the kind's `…Orphaned` Warning (`auraDeleteRefused`, id 201); an `AuraDatabase` whose `AuraInstance` CR is gone releases at once, with a Warning (id 202). A status message built from an Aura error goes through `aura.MessageWithoutRequestID`, so a failure that repeats is the same status, and the `AuraProviderConfig` revalidates every 10 minutes, wired with no `RequeueAfter` (id 184). ## Key types & functions

- `ResolveClusterRef(ctx, c, ns, name) (ResolvedTarget, error)` — tries cluster first, then standalone (`cluster_resolver.go`). `ResolvedTarget` exposes `IsReady`, `NewClient`.
- `EnqueueDependentsForClusterChange(...)` — watch wiring so user/role/binding reconcilers re-run on cluster status flips (used in each `SetupWithManager`).
- `SetReadyCondition` / `SetNamedCondition` (`conditions.go`) — `SetNamedCondition` for `ServersHealthy`/`DatabasesHealthy` etc.; `SetReadyCondition` ONLY for the `Ready` type.
- `(r *Neo4jEnterpriseClusterReconciler) envVarsEqual(...)` + package-level `mergeEnvVars(...)` (`neo4jenterprisecluster_controller.go`).
- `MergeNeo4jPluginList(existing, newPlugin)` (`plugin_controller.go`) — live-patch `NEO4J_PLUGINS` without clobbering other controllers.
- Each reconciler's `Reconcile` + `SetupWithManager`.

## Conventions & gotchas

- **Validation is INLINE, never a webhook (invariant 1).** Reconcilers hold a `*validation.*Validator` (e.g. cluster controller's `Validator *validation.ClusterValidator`) and call it from `Reconcile` — there is no `_webhook.go`.
- **Status writes wrap `retry.RetryOnConflict(retry.DefaultRetry, ...)`** (or `DefaultBackoff`) — required for 2025.01.0 cluster formation. See `neo4jenterprisecluster_controller.go` (`grep -n RetryOnConflict`). Re-fetch the object inside the closure.
- **Never `Update` one of the operator's CRs; patch what you change** — a finalizer, an annotation, a spec field (`object_patch.go`: `patchObject`, `addFinalizer`, `removeFinalizer`; knowledge `operations.md` id 150). An Update sends the whole object as the Go types encode it: the cluster reconcile's copy carries `ApplyDefaults`' defaults, a `false` the CRD defaults to `true` is omitted and comes back `true` (a `Neo4jRole`'s `enforcePrivileges: false` turned into revoking), and a quantity is re-spelled. `TestReconcile_LeavesTheSpecAsApplied_APIServer` and `TestFinalizers_LeaveEveryKindsSpecAsApplied_APIServer` (envtest) pin the writers. Child objects (StatefulSets, Services, ConfigMaps) are the operator's own and are not covered.
- **Per-server clients use the cluster's admin Secret with its default** (`getClusterAdminSecretName`; `dialClusterPod`, `createPodSpecificNeo4jClient`; knowledge `operations.md` id 132): never refuse a cluster without `spec.auth.adminSecret`.
- **StatefulSet existence check is `sts.UID != ""`, NOT `ResourceVersion`** (ResourceVersion is set even on never-created objects). See `createOrUpdateResourceInternal` in `neo4jenterprisecluster_controller.go`.
- **Emit events via `EventReason*` constants from `events.go`** with `corev1.EventTypeNormal` / `corev1.EventTypeWarning` — never raw strings.
- **Env vars: subset-merge, never wholesale-replace.** `envVarsEqual` checks desired vars exist with the right value but tolerates foreign extras; `mergeEnvVars` merges and enforces removals via the owned-keys annotation (`owned_keys.go`). Each `Neo4jPlugin` keeps the same kind of record of the vars it sets (`neo4j.com/plugin-env-vars.<plugin>`) and removes only what it recorded, never a var the target's own record or another plugin claims (knowledge `operations.md` id 155). Do not bake `NEO4J_PLUGINS` into the static StatefulSet template; use `MergeNeo4jPluginList`. (CLAUDE.md "Key Implementation Patterns".) Init containers and volumes of the server pod template follow the same model by name (`mergeOwnedByName`, `readOwnedTemplateItems`; knowledge `operations.md` id 141) — a `VerifiedDownload` plugin's init container is not the cluster's.
- **`CollectDiagnostics` is non-fatal** — surface errors to `status.diagnostics.collectionError`, never `return err`.
- **Server-based naming only**: `{cluster}-server-0…N-1`; never `primary-*`/`secondary-*` (invariant 5). `splitbrain_detector.go` enumerates pods by this scheme.

## Tests

`*_test.go` here run under the envtest suite (`suite_test.go`, no real cluster). Run the whole package with `make test-unit`, or directly: `go test ./internal/controller/...`. The core/extended ginkgo label split lives in `test/integration/`, not in this package. A single integration spec: `make test-one TEST="name"`.

A test writes one of the operator's CRs with a patch, never a whole-object `Update`: `patchObject` / `removeFinalizer` in the package's unit tests, `patchCR` / `patchJSON` / `releaseFinalizers` (`spec_writes_test.go`) in the Ginkgo suite. An Update leaves out a `false` the CRD defaults to `true` and it comes back `true`; a deliberate one carries `// cr-update-ok: <reason>`. `make check-test-cr-updates` reports the rest (advisory; knowledge `operations.md` id 205).
